# Disabled P2 reader/dispatcher requalification package

This package prepares and audits exact source/reader contracts. It does not
install or qualify a live dispatcher. No Stata, worker, participant or model
payload is invoked. C2 remains HOLD. Every original and prior packet is preserved.

## Two separate tracks

| Track | Exact proposed structure | Current status |
|---|---|---|
| Protected TARGET33 proposal | P1 → corrected P2 → P3 → P4; one previously proposed participant load in P1; unchanged literal163-field scope | Not authorized, not dispatched, current access/output/runtime gates open |
| Artificial suite | A1–A5 bind the five preserved case files; fresh empty owned runtime per case, not a shared four-step session | Native NOT_RUN; source and artificial metadata consistency only |

The artificial files can leave rows/variables in memory. Each future file needs
independent empty admission (N=0, K=0) and a fresh owned runtime. The five files
must not be appended to the old four-selection sequence or assigned its budget.
Actual ownership, empty-state observation, cancellation and closure evidence
are still unqualified. No real process is created or stopped by this package.

## Source-exact binding

BINDINGS.json records paths, byte counts and SHA-256 for both held sources and
their prospective payloads. The single proposed transformation removes only
the first executable `exit 198`, preserving every other byte. It is computed
in memory only. No unheld source file is written; no activation is authorized.

P2 is 952,852 bytes as saved; its prospective payload is 952,843 bytes. The
legacy P2 is 956,192 bytes. Updating an old file reference alone is insufficient:
old digest guards reject it, and executing the held file would only stop at198.
A future reviewed provider must verify both identities, apply only the exact
authorized transformation and hand off the same checked byte buffer. Do not
strip holds, split bodies, extend limits or select another transport here.

## Reader compatibility and receipt inventory

The pinned, preserved pure reader derives ordered templates from the known
Stata file-write grammar. This package calls only that parser/reader and the
existing in-memory ArtificialTransport. It never calls legacy load_plan,
native providers or the fixed-file live/control path.

The new P2 inventory contains **4,129 rows**, versus 4,139 historically. The
ten removed subtype rows are exactly q10_1/q10_2 option-4 uncertainty receipts.
The nine columns and 500 six-state field/version partitions remain unchanged.
Unchanged output inventories are P1: 9 rows, P3: 39 rows, P4 coverage: 121 rows,
plus one readout-text template. Source-derived template digests are frozen.

In-memory tests show the preserved reader accepts an artificial receipt bound
to the new template and rejects old/new inventory cross-use, missing/extra rows
and malformed counts. The preserved dispatcher rejects the new P2 digest
before simulated selection; the old baseline remains artificial-only.
No resulting count is a study finding or a native test output. Mock counts use
the old 423-row reference solely to exercise the preserved format contract.

MIGRATION_MAP.csv identifies seven concrete consumer changes/gates. Existing
readers, dispatchers, seals, source manifests and fixed-file guards are not
edited. The current parser is source-compatible when given the new inventory;
that does not requalify its old loader/admission path or any runtime.

## Artificial evidence/readout contract

The five case descriptors contain **62 named required facts** from the literal
case catalogue and explicit assertions: state comparisons, denominators,
sentinels, semantic contradictions, all 11 own-N and three common-N values,
primary counts, empty bases and the negative assertion's exact statement.

check_case_record rejects wrong scope/case/source/payload, missing or extra facts,
wrong values/types, participant loads, fits or retries. Booleans are not integer
counts. An as-saved198 record is HELD_NOT_TESTED. The negative case accepts the
expected9 only at its range assertion, never an empty-memory guard failure.
Positive outcomes require a complete-payload phase, not a start marker.

Its successful return is deliberately
`ARTIFICIAL_METADATA_CONSISTENT_NOT_NATIVE_VERIFIED`. Artificial records used in
these tests are self-authored dictionaries. The function does not authenticate
actors, independently observe execution, extract a real stdout/log, validate a
signature or prove cleanup. Real capture/extraction and independent provenance
remain an explicit hard gate; do not fabricate facts from expected values or
promote a consistent record to native success.

## Files and finite audit

- offline_contract.py: known source descriptions and pure artificial-record checks;
  no worker, network, shell or Stata interface.
- test_requalification.py: only file/metadata and in-memory artificial receipts.
- BINDINGS.json and MIGRATION_MAP.csv: exact proposal, consumer deltas and holds.
- source_pins.json: preserved existing source/metadata custody, not participant data.
- AUDIT.md, REVIEW.md and VALIDATION.json: final scope, review and checks.
- COMMIT_MESSAGE.txt: proposed title/description; no commit performed.

Run only the named pinned CPython checker and named predecessor metadata checks.
No repository-wide discovery or native tests. No source is scored or fitted,
no real output destination is provisioned and no service/setting is changed.
Existing 45/180/30/210-second participant proposal limits remain unadopted and
unchanged; no artificial-case runtime budget is selected or inferred.

Completion means this offline requalification package is prepared and audited.
It does not resolve scientific, institutional, disclosure, coauthor, release,
source-exact execution or current participant-access decisions. C2 stays HOLD.
