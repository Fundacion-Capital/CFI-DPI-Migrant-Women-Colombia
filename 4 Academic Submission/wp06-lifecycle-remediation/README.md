## Implemented boundaries

**One terminal result, not repeated cleanup effects.** The owned manager caches its terminal outcome and returns defensive copies. Bootstrap-pending state is reserved atomically before the first interruptible guard. Pending allocation or initialization, an in-progress cleanup and a completed failed cleanup are distinct. The tool wrapper consults the manager rather than claiming closed before the manager returns. Bootstrap errors remain chained to their original cause. Interruptions and terminal-record failures cannot become accepted output. The non-authoritative `parent.cleanup.pending` candidate is fully written, flushed, file-synced and closed before an exclusive hard-link publication creates `parent.cleanup.json`. A candidate alone is never final evidence. Failed candidates remain preserved; no final record is replaced and no write is retried. Publication/flush/close failures yield an explicit unsuccessful cached outcome. This filesystem protocol is tested on artificial temporary files, not credited as a native-runtime or power-loss guarantee.

**Observations before disposal.** Rollback records retained process identities/exit codes and owned-job inventory before closing its capabilities, then separately records closure attempts/failures. Nonzero failed-child exit status is not confused with successful execution: it may establish observed containment but cannot make a failed recipe accepted. Completed rollback metadata is reused without querying closed handles. Provider control and handle disposal share a narrow capability lock; disposed/rollback capabilities cannot be retargeted. The manager preserves its independent deadline-control path during cleanup. Closing admission is not proof of physical cleanup.

Outstanding capability-producing operations also remain pending: the supervisor cannot publish completed rollback while a worker/watchdog creation is still returning. A cleanup request closes later creation admission. The same acquisition attempt registers and contains any returned capabilities before terminalization; it never creates a replacement. The supervisor continues to report pending rather than claiming completion. If an underlying native API does not return, cleanup remains unestablished—not a successful deadline claim or an extended budget. Native boundedness still requires its own authorized evidence.

**First evaluated bootstrap rejection.** The role entry preserves schema, role, digest, frequency, creation-identity and original 60-second deadline checks. The actual producer emits dictionaries; malformed non-dictionary input now receives an explicit schema rejection rather than an incidental indexing failure. Each later operand remains `NOT_EVALUATED` when an earlier predicate rejects. The single sampled guard tick is retained only when reached; no origin reset or added grace is used. Fixed role-specific private filenames, a 4,096-byte ceiling and exclusive creation prevent arbitrary payload paths/overwriting. Raw bootstrap keys, credentials and full payloads are never recorded. Disk-source hashes are explicitly disk identity, not loaded-memory attestation. An observation/diagnostic-write error cannot produce acceptance.

The original two literal empty-session selections, nominal ten-second tool arguments, one worker/session epoch, zero retries/replacements and 60/80/90/95/100/110/120-second design ceilings are unchanged. No empirical `.do` file, measurement, sample, model, LCA result or manuscript was changed.
