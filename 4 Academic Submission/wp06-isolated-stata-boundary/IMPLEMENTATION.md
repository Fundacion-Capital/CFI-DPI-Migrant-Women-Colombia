# WP06 — isolated Stata-MCP boundary, artificial-only implementation

29 October 2026

## Result and scope

This package implements the **ownership/admission/no-replacement policy and source-method compatibility layer** specified in the preceding [empty-Stata contract](../wp06-empty-stata-contract/EMPTY_STATA_INTEGRATION_CONTRACT.md). It does not implement or deploy a live Stata-MCP service. There is no Stata/native process provider, service endpoint, launch command, credential discovery or flag that enables one. The allowed effect domain is `ARTIFICIAL`; real-domain providers and runtime-ready claims are rejected.

The owner's instruction authorizes implementation and artificial-only tests, preserving prior packets, without Stata launches, participant processing or shared-service changes. All changes are additive in this folder and a new restricted evidence packet. The earlier contract folder remains untracked at entry and is preserved just like committed sources; it is not silently incorporated into a commit.

## What the code does

`boundary.py` creates a **new isolated class** combining the policy with the reviewed manager's selected execution method. It does not patch an installed class, existing manager or service. Its constructor does not call the legacy manager constructor, start a cleanup thread or create a default worker.

`bind_dispatcher(manager)` captures one exact manager instance in a closure. Its dispatcher accepts exactly `selection`, explicit `session_id` and integer `timeout=10`; there is no candidate-manager argument on the wire or at later dispatch. Binding rejects absent/wrong managers; dispatch rejects disabled multi-session mode before delegation. The server's legacy single-session direct-execution fallback is not used. This is in-process binding, not authenticated external service/role deployment. The only permitted application inputs are the two literal selections from the preceding contract, in their specified order.

Ownership proceeds once: reserve creation, allocate a suspended artificial resource, freeze returned capabilities, assign its job, observe and bind the physical identity, then initialize. Closing while allocation is in flight records deferred cleanup rather than falsely finalizing it. When capabilities return, initialization is refused and retained-resource cleanup completes. Each command rechecks the same run/session/epoch, PID and creation time, retained artificial process/job capabilities and clock domain. Initialization must precede admission but follow ownership. Source hashes are provenance constraints on the test loader, not a claim of loaded-runtime attestation. A future native allocation provider must internally contain/roll back partial allocations if it raises before returning capabilities; this package has no such native provider and does not claim that obligation is proven.

The installed `execute()` definition is exercised in compatibility tests, while its creation/preparation, command transport, recovery, wait and lifecycle paths are replaced in the **new isolated class** by explicit guards. Recovery, restart, implicit creation, file/data runners, default-session lifecycle actions and the original timeout waiter cannot be reached through the admitted manager interface. A transport error consumes the call and closes further admission; observing a recovered result never legitimizes a replacement. Original source/class objects are not modified.

The source helper removes the final newline from each submitted literal. The boundary therefore checks the exact original literal at admission and exactly that one-newline transformation at the transport boundary. It does not permit arbitrary normalized code. The first compatibility failure and its correction remain recorded.

The monotonic artificial clock enforces the inherited design ceilings: bootstrap before 60 seconds, dispatch before 80, nominal call deadline 10 seconds, control/containment at 90/95/100/110, and final evidence/closure before 120. These are unadopted design values, not measured Stata performance or real-time OS guarantees. Control uses a separate provider operation outside the request lock and remains callable during request waiting and cleanup. Actions are consumed before effects, once only. Actual independent scheduling/native enforcement is not established by these in-process tests.

Cleanup verifies owned exit/identity/inventory evidence, attempts all retained handle closures even after an individual error and cannot accept a still-pending second call. Identity-observation errors remain failures but do not suppress shutdown or exit witnessing through the original retained capabilities. No new target is resolved from changed metadata. Two completed valid calls—not merely two attempted calls—are required. Failed, late, malformed, recovered, identity-changed or incompletely closed runs cannot pass. The provider remains responsible for the effects it reports; artificial observations are not native witnesses or a hostile-same-user security sandbox.

[manifest.json](manifest.json) pins every Python file under the installed extension's `src` directory, its package description, the exact preceding contract, the implementation/test sources and the interpreter actually used for artificial tests. Imports are enumerated by AST without importing the extension, PyStata or its dependencies. Name classifications are navigation/provenance metadata, not proof of the live worker's package environment. Dynamic import sites and external dependencies remain explicitly unresolved where applicable.

The manifest records required startup boundaries: ownership before engine initialization, explicit epoch, reviewed engine/PyStata/profile dependencies, no hidden loads or populated other frames, and all seed/log wrappers. It records required output isolation for worker/debug/selection logs, cwd, temporary/graph/history locations and create-only evidence. It identifies the future dispatcher/manager factory and exact parameter schema but supplies **no endpoint, usable credential, native provider or launch entry point**.

**The manifest is intentionally not a complete runtime deployment attestation.** The live worker interpreter/environment, third-party transitive code, engine/PyStata/startup profiles, native control provider and exact private output/deployment bindings have not been observed or adopted. `runtime_ready=false`, startup review `UNBOUND` and deployment `NOT_DEPLOYED` are required states. The Python interpreter pinned here is the artificial test interpreter only, never a guessed identity for the live service.

The selections still describe **active-frame dimensions only**, not the absence of other frames or stored objects. No selection was sent to Stata; no dynamic Stata syntax, engine capacity, busy interruption, participant safety or empirical reproducibility claim is made.

The concurrency case uses an in-process Python thread and artificial events; no native process/worker is launched.
