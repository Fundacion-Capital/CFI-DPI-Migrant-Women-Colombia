# WP07 TARGET33: disabled fixed-file transport

This is an offline acceptance fixture, not a Stata runner or a replacement for
the dispatcher. It has no provider, launcher, or participant-data route.
P1 uses the sealed artificial no-load substitute; P2–P4 are read as source
bytes only and are never interpreted. Cancellation uses its own artificial
owner and fixture, not a fifth capacity call.

The descriptor binds the artificial scope, owner, sequence, stage, byte length,
digest and deadline. It carries neither a path nor executable text. The
consumer matches the one authenticated reservation, then reads from the fixed
manifest and checks the same immutable bytes passed to the fake worker.
P2 is 956,192 source bytes; its reference in the capacity audit is 265 bytes
against an 8,192-byte ceiling (the reference length can vary with deadline digits).

Time limits are exclusive: 45 seconds per reservation, 180 for work, and
30 from completion/stop observation for cleanup, capped at 210 from origin.
The separate in-process stop capability is accepted only by its own busy
cancellation fixture, through busy second 40 and before the selection deadline.
The test blocks the fake worker while another thread requests stop; the worker
is released by the test and cannot report success. Simulated exit evidence
requires both exits, no active owned target and no retained handles. Bad or late
closure is held and cannot be retried in that fixture.

Run `audit.py` with Python 3.11 in isolated, no-bytecode mode
(`-I -S -B`), then repeat with `-O`. It verifies four predecessor seals
and their 31 exact members before and after the fixture tests. It installs
launch, network and common dataset-open tripwires for the audit interpreter.

The fixture proves neither native interrupt delivery nor actual target exit,
runtime startup, or filesystem isolation under a live service identity.
The previous runtime and any protected execution remain disabled. Before any
live qualification, recheck exact empty-runtime readiness and obtain separate
authorization. Restricted readers/operators, output isolation and retention
for successful, partial and failed packets remain decisions, not approvals.
