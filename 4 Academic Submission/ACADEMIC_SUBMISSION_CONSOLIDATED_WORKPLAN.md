## 2. New operating rules

1. **One work package, four substantive subprocesses, one final handoff.** Do not stop after source intake, adapter preparation, readback or report drafting if the next action is within the approved package and its internal gate passes.
2. **Keep granular IDs as traceability, not conversational boundaries.** Map their receipts to the package; avoid manufacturing extra public stage IDs for routine fixture/parser fixes.
3. **One package-entry preservation manifest and execution scope.** Snapshot the actual working tree, including inherited uncommitted files and approved untracked carryover. Do not require an artificial commit between subprocesses. Never overwrite earlier packets; immutable child execution attempts remain inside the new package boundary.
4. **Keep execution reservations internal.** Each real Stata execution remains source-bound and separately identified, but issuing that reservation does not by itself require another user turn when the package already authorizes the operation.
5. **One meaningful final independent review.** Run local tests throughout, then review the combined result, resolve findings and run a fresh final audit. Add another scientific review only for a materially different question or a genuine unresolved finding—not for every serializer or metadata file.
6. **Preserve failures; distinguish technical and scientific outcomes.** A documented mismatch/nonconvergence may complete a historical disposition. It is not a reason to keep fitting until the expected result appears. A parser/reader repair does not earn scientific acceptance.
7. **Do not weaken checks to make a batch finish.** Retain source hashes, exact native targets where available, declared precision, unavailable-value distinctions, respondent boundaries and output-path protection. Never reuse a spent no-retry fit reservation.
8. **Bound repairs by their effect.** A separately preserved, statistically inert parser/reader/fixture correction inside the approved scope can be handled within the same package. Stop before a scientific change, a repeat fit not in the manifest, or a change to protected source evidence. After three unsuccessful corrections of the same technical failure, reassess and report rather than iterate blindly.
9. **Authorize estimates by an explicit batch manifest.** Before a fit-bearing package begins, name every model/source range, input, seed/start setting, iteration/runtime ceiling, maximum fits and retry rule. One owner approval can cover the whole named batch. No blanket authority for arbitrary future estimations or revised specifications is inferred.
10. **Preserve the historical/revised divide.** M6 reproduces/disposes of historical evidence. M7 records justified revisions and material author decisions. M8/M9 execute the revised academic plan. Broad tasks do not erase that dependency.
11. **One concise end-of-package delivery.** Supply completed outputs, tests/review, unresolved scientific decisions, exact next package, and a proposed commit title/full description. Do not commit, push, sync Overleaf, submit or publish without the corresponding authority.
12. **Use resource checkpoints, not artificial permission checkpoints.** If runtime/context/tool limits interrupt a long package, save a durable continuation record and resume from it; do not promise uninterrupted execution or mistake a client timeout for a failed fit. Check durable logs before any further dispatch.

### Stop only for a real boundary

Stop for missing required evidence/access; consent/privacy/rights problems; an exhausted authorized fit budget; unverified preservation; a substantive design/measurement/primary-claim choice; conflicting protected qualitative material; or repeated technical failure requiring a changed approach. Explain what can still be completed safely and preserve the unfinished package. Do not call a scientifically unresolved package complete merely because its code runs.
