# WP06 additive startup remediation

This is an implemented, disabled successor to the sealed native-empty provider. It addresses the accepted startup review without editing the predecessor, historical packets, installed runtime, global configuration, manuscript, analytical code or participant files. Current acceptance is source/artifact integrity and artificial/no-execution verification—not a native launch, startup proof, scientific validation or approval.

## Implemented corrections

| Boundary | Successor behavior |
| --- | --- |
| Child environment | Explicit Windows `System32;Windows` PATH plus SYSTEMROOT, private USERPROFILE, TEMP, TMP and STATATMP. No inheritance of the full host PATH by target roles. |
| Run preparation | Exact authority and complete inventory/identity checks precede create-only preparation. A new root, empty home/temp, two fixed comment-only profiles and a binding/scope-bound receipt are created. Existing roots and partial failures are preserved, not emptied or replaced. |
| Attachment | Channels, active-binding loading, process creation and engine initialization verify the prepared startup boundary. Attachment never recreates missing directories. Unknown root inputs, nonempty home/temp, changed profiles/receipt, reparse startup paths, foreign scope and installation-profile precedence are rejected. |
| Windows SDK imports | Under `-I -S`, explicitly expose the installed SDK's required win32 directories and use a scoped DLL-search handle after authority. Do not execute `.pth` code or install dependencies. Restore the process import path when the SDK context closes. |
| Isolated client | A one-use exact stdio client performs initialization, initial session metadata, the two unchanged selections and final closed-session metadata. No shared URL, default session, recovery branch, retry or replacement is used. |

`startup_guard.py` supplies the small common boundary. The copied callers are changed only where required to enforce it. `native_session.py` and `native_provider.py` remain byte-identical to the predecessor; the manager execute/join source, selection payloads, ownership/control logic and analytical history are not rewritten. The server's SDK lifetime is wrapped explicitly, without changing its dispatcher or tool handlers.

The private profiles contain only this comment: `* WP06 empty-runtime startup: no commands, data or external sources.` They introduce no Stata commands. Installation-directory profiles are checked first because they have higher search priority. The proposal follows documented Windows search order; actual native behavior is still unmeasured. See [Stata's Windows startup manual](https://www.stata.com/manuals/gswb.pdf).

Only named Python test interpreters run. Final source-bound normal/optimized receipts, predecessor tests, independent review, full preservation audit, exact checkpoint seal and separate readback govern completion. The reviewer did not independently endorse the subsequent correction or perform native acceptance.
