# Minimal next package — disabled failure detection and native-return evidence

## Recommendation

Prepare one additive **disabled fail-fast/bootstrap-return-evidence successor and artificial-only acceptance package**. Do not make another speculative loader change. The current evidence proves an observability/failure-detection gap, but not the internal discovery cause. This proposal does not fix or authorize a runtime, clear participant/scientific/institutional gates, or supply a trial grant.

## Change 1: stop waiting when the retained role has already exited

In the parent's watchdog-ready and worker-ready phases, use the already-owned role handle/identity to reject early exit while awaiting the exact authenticated frame. Do not scan host processes, open foreign PIDs, replace a role, add a generic recovery loop, clear data or extend a deadline. A frame plus an exited role is not successful readiness. Keep the existing 60-second upper bound and all later controls; route failure through the existing once-only rollback.

The current `Channel.wait` checks only for a frame and a deadline. The new behavior should be explicit at the parent/role boundary, not a broad fallback added to every channel operation. Required actual-frame authentication and exact run scope remain unchanged. This changes failure latency/reporting, **not** the ability of Stata to locate Python.

## Change 2: retain the native initialization return and executable handoff

Retain, within the existing 8192-byte diagnostic budget, the exact raw/resolved Python executable strings handed to initialization and the actual integer return from the pinned vendor `_init_stata` boundary, if reached. A small worker-local, temporary wrapper around the pinned function is one possible design: delegate exactly once, preserve its return/exception and restore the original in `finally`. Do not patch vendor files, alter return values, skip configuration, suppress errors or turn an unobserved code into `-7100`.

This uses an internal vendor interface, so it needs exact source-version pinning and artificial forwarding/restoration tests before adoption. If that interface cannot be wrapped transparently, hold this instrumentation rather than redesigning vendor initialization. Record “not reached” when appropriate; never fabricate a native return. Bind every record to the new source digest and exact run scope. No full environment/sys.path/module dump, new executable probe or registry query is included.

## Explicit nonchanges

- Same base/SDK interpreters, Python DLL and SFI disk pins; no distribution installation or interpreter switch.
- Same isolated flags, six-field environment, process-local DLL-directory handling and existing startup profiles. No PATH/PYTHONHOME/PYTHONPATH/registry/service/global-settings change, canonical-path substitution or extra SFI import root.
- Same two literal empty selections, nominal selection limits, no retries/replacements and 60/80/90/95/100/110/120-second controls.
- Same owned jobs/handle restrictions, six runtime-identity families, positive SFI/plugin requirements and private-cache proofs. No relaxed success conditions or adoption of a failed result.
- No participant processing, fitting, analysis/methodology/manuscript change, publication or coauthor/institutional approval inference.

## Artificial acceptance before any future authorization

Test role exit before readiness; on-time live-role readiness; missing/late/malformed/foreign frame; simultaneous frame and exited role; both role types; exact once-only rollback; no second creation/replacement; and unchanged clocks/deadlines. Use fake kernel/channel objects only. Test the temporary vendor-boundary wrapper with artificial functions returning zero, negative/handled failure values and exceptions: forward once unchanged, retain typed evidence, restore on every path, reject unknown source/schema and stay within the metadata limit. Keep native effects denied throughout.

Negative fixtures must show that no source/ready/status success is published after role failure, missing positive SFI or evidence-publication failure. Preserve failed fixtures and all earlier packets. Reuse the existing qualification/sealing machinery; do not add another general execution framework.

## Later decision, not current authority

After artificial acceptance and a source-exact owner checkpoint, a separately authorized single empty trial could test this diagnostic successor. The expected benefit is earlier, better-scoped failure evidence, not promised startup success. Select a loader/environment/interpreter remediation only after that evidence discriminates among the remaining causes; change one justified variable, not several guessed ones. A larger redesign or vendor-support contact would require separate direction.

No implementation of this successor, native launch, grant, contact or settings change is performed by accepting the present diagnostic account.
