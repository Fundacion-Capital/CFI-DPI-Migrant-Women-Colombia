# WP07 block 05 — owned-worker control and logging audit (R03)

**Protected dispatch remains held.** One artificial busy attempt ran; the stop was not sent. The owned stop route and native idle exit were verified, but busy cancellation and no-replacement behavior after a busy stop were not.

| Check | Evidence |
| --- | --- |
| Owned hard-stop route | The exposed Stata MCP named-session `destroy` route was bound to one fresh non-default worker. The listener identity, new direct child, first-run seed derived from the worker name and PID, owned startup log, and Windows creation time agreed. The native observer opened a query/synchronize-only handle before dispatch. No hidden HTTP stop or OS kill was used. This is a hard-stop route for a busy worker, not the separate Stata Break action. |
| Single busy attempt | The observer's 4-second marker window expired without a closed witness. The marker was written **5.080 seconds** after client dispatch; the observed native start was also delayed. The selection completed naturally, with the completion witness at **30.080 seconds**. No busy stop was issued, the first handle timed out without an exit signal, and the busy trial was not repeated. |
| Native idle closure | After the same session returned idle, one named MCP destroy closed it. A second retained handle to the same PID and creation time became signaled with native exit code **0**. The registry and process-child readback showed the worker absent, and owned server log records showed one creation, one destroy, and zero restarts. This proves no observed replacement in the idle cleanup window only. The default session was unchanged. One other pre-existing session disappeared through its own server-recorded idle timeout; no command targeted it. |
| Server log | The active shared server durably recorded the **full artificial selection and working directory in the request URL**, including content beyond its short selection preview. This is not the reserved protected directory. A local-only result writer does not protect the selection text on this route. |
| Worker and Stata logs | An owned debug log remained in the Windows temporary directory after idle exit. It identified each per-call Stata capture file in the same temp area; the worker read the capture and the completed-call files were absent at readback. The synthetic result canary was returned in the ordinary MCP response. Whether an abruptly terminated worker leaves a partial capture was not tested. |

The original guarded emitter, protected carrier and destination, settings, service code, and predecessor packets were untouched. No participant load, fitting, Git stage/commit/push, or publication occurred. Only the fresh artificial worker was targeted. Exact synthetic selections, scoped log evidence, and handle events are retained in the ignored audit packet.

**Disposition:** Before any protected call, use a demonstrably confined selection and logging route; the active route is not qualified for that use. A new, explicitly bounded artificial busy-stop attempt would need a dispatch window that covers the observed handoff latency, a watcher that polls for the exact closed marker, a fresh same-worker busy check, and a no-late-stop deadline. Require native exit before natural completion, no completion witness, settlement of the original RPC, and no replacement across the monitored window. Do not substitute the idle result.
