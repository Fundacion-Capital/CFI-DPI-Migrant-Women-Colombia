# Academic research workflow

Start project work with `4 Academic Submission/00_CURRENT_WORKPLAN.md` and
`4 Academic Submission/00_meta/current_workplan.json`. They give the current
sequence and checkpoint. Older workplans, workflow-state entries and audit
packets remain preserved history, not renewed execution authority.

The objective is the complete academic paper from the selected full legacy
manuscript: literature/theory, Colombia context, quantitative research,
coauthor's qualitative evidence, expert/institutional analysis, regional
benchmarking, discussion and technical supplement. Stata revision is one phase.

- Prioritize the actual master/preparation/analysis do-files. Use clear native
  Stata, direct commands and explanatory comments. Avoid unnecessary helper
  programs, fallback machinery or generic reporting frameworks. Ordinary macros
  and loops are fine when they make a real statistical operation clearer.
- Statistical execution uses Stata MCP when authorized. Do not replace it with
  Python/R estimates or shell-launched Stata. Python/worker/bootstrap development
  is not a research milestone or replication-package requirement. If execution
  is unavailable, report the bounded limitation and continue permissible source,
  literature and manuscript work; do not start infrastructure development.
- Preserve originals and accepted decisions. Distinguish style fixes, coding
  corrections, approved scientific revisions and material decisions still needed.
  Never force revised results to match historical numbers or choose for significance.
- No participant/model loads, fits, expanded data scope, releases, contacts,
  commits, pushes or live Overleaf sync without the corresponding authorization.
  Keep C2 on hold until its separate conditions are resolved.
- Review the scoped Zotero collection and original literature; use only the
  author's public NotebookLM project link, without authentication repair.
  Primary sources govern citations and chronology, not notebook-generated text.
- Integrate existing qualitative findings, not recode transcripts or change the
  coauthor's empirical themes/quotations without explicit scope and review.
- Work in substantive packages with internal checks and one meaningful final
  review. Do not require a new user turn for each harmless check inside scope.
- End each implemented package with actual evidence, remaining limits, next
  substantive task and a full proposed commit title/description. Do not commit.
- Update the current checkpoint only to what the evidence supports. A plan,
  source audit or successful tool test is not empirical/scientific approval.

This guidance does not broaden a user's current task or override their limits.
